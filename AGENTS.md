# Agent guide: graph-platform

> Keep `AGENTS.md` and `CLAUDE.md` byte-identical. Update both when a new durable convention or gotcha is learned; check current code before documenting behavior. ADRs in `docs/adr/` explain design decisions. Never commit credentials.

## Map and ownership

This repository combines Python 3.14+ (`uv`), an ASP.NET Core 10 management API, and a Vite/React SPA. Three independent Python projects each have a `pyproject.toml`, `.venv`, and `uv.lock`; service projects depend on `common` by editable path, not on one another. There is no root Python project.

| Location | Package | Responsibility |
|---|---|---|
| `src/common/src/common/` | `common` | Shared domain/Pydantic schemas and DTOs, ORM mappings and reads, AGE repository, lifecycle service, embedding service/index DDL, storage abstraction and providers |
| `src/agent-runtime/src/agent_runtime/` | `agent_runtime` | Graph agent, tools, prompt, context, serializers, chat-model adapter |
| `src/ingestion-worker/src/ingestion_worker/` | `ingestion_worker` | Ingestion writes, API-owned job-state access, Celery dispatcher/stages/tasks, legacy one-shot demo |
| `src/api/` | .NET `GraphPlatform.Api` | Management HTTP API, auth, EF-owned schema and storage/file writes |
| `src/frontend/` | GraphForge | React management SPA consuming the API over HTTP |

- Put a module in `common` only if multiple services need it, or it is shared domain/database schema (ADR-0004). Do not move ingestion-only writes into common: `ingestion/graph.py`, `extraction.py`, `writer.py`, `pipeline.py` are worker-owned; `KnowledgeBaseService` owns graph/KB lifecycle and read/search only.
- Python's `Base.metadata` owns `graph_registry`, `schema_embedding`, `node_embedding`; EF migrations own `organization`, `user_organization`, `model_config`, `knowledge_base`, `file`, `knowledge_base_file`, `index_job`, `index_file`, and Identity tables. `ApiOwnedBase` maps shared API tables without putting their DDL in Python `create_all`; worker job models use a separate `IndexJobBase`. EF must not migrate Python-owned tables.
- Import common leaf modules directly. `models/__init__.py`, `services/__init__.py`, `repositories/__init__.py` deliberately have no re-exports; `schemas/`, `database/`, `storage/` have no `__init__.py`. `SchemaEmbedding` and `database/indexes.py` are leaves below `GraphSchemaRegistry`; preserve this direction to avoid import cycles. Check new import paths in a fresh interpreter (pytest import order can hide cycles).

## Python schemas, models and configuration

- `schemas/knowledge_base.py` defines graph-payload `KnowledgeBase`, `KnowledgeNode`, `KnowledgeRelationship`, **not** ORM mappings. Missing IDs are generated as UUIDs; explicit `id: null` is not repaired by `setdefault`. Extraction raises `ValueError` for a falsy KB ID. `dummy_data/f1_kb.json` has a stable ID for repeatable ingestion.
- ORM-facing Pydantic DTOs (`from_attributes=True`) live beside their model schemas: `KnowledgeBaseRecordDTO`, `FileDTO`, `GraphSchemaRegistryDTO`, `SchemaEmbeddingDTO`, `NodeEmbeddingDTO`. Extraction returns DTOs; the worker writer maps them into ORM rows. API-owned KB resource and graph-payload `KnowledgeBase` are distinct. KB content is **files only**: the old `Data` graph-JSON column was removed. `KnowledgeBaseRecordDTO.files` contains `FileDTO`s with storage keys, oldest first.
- Shared API-owned `models/knowledge_base.py` maps PascalCase EF columns; its one-way `files` relationship uses `knowledge_base_file` as `secondary` and `lazy="selectin"` for async DTO conversion. `models/file.py` is an owner-agnostic leaf with **no relationships**; other owners add link tables, never owner columns on `file`. `KnowledgeBaseFile.file_id` is the PK (a file links to at most one KB); both FKs cascade.
- `schemas/model.py`'s `Model` is provider configuration (no Python ModelConfig ORM). Its `id` is a required, caller-assigned, valid UUID string, stable across restarts; `identifier = f"{provider}/{name}"` is only the litellm call name, never embedding provenance. `type` is nonempty; embedding is mutually exclusive with vision/thinking, requires `embedding_dimension`, forbids `reasoning_effort`; API-key auth requires an API key. YAML's `api_key_env` resolves into the secret before validation. Chat-only `reasoning_effort` is allowed.
- `AppSettings(path)` parses YAML once; `AppSettings()` reads no file. `load_config()` updates the existing `settings` singleton **in place**. No global embedding dimension or config-before-model-import constraint: vector columns are dimensionless. `configs/local.yaml` is the runtime template; invalid/blank entries and unset referenced secrets fail loudly. Each Python service loads config in its entrypoint.
- Logging is per service: each service validates only its own `<service>.logging` YAML section (`ingestion_worker`, `agent_runtime`) with common `schemas/logging.py` `LoggingSettings` (blank = default INFO/stdout; `file` requires `log_file_path`; unknown keys fail) and applies it with `common.logging_setup.configure_logging` (root `dictConfig`, idempotent). Service sections stay out of `AppSettings`. The worker applies it through a Celery `setup_logging` receiver in `celery_app.py`, so Celery's `--loglevel` is ignored for worker and Beat.
- Use SQLAlchemy 2 `Mapped`, Pydantic validators, async sessions, and in-memory SQLite for ordinary tests. Check ORM-to-DTO transfer without triggering async lazy loads.

## Ingestion and knowledge-base lifecycle

- The legacy, separate `ingestion.pipeline.ingest_knowledge_base(session, repository, kb, graph_name, organization_id, model=None)` merges nodes/edges through `AgeGraphRepository.merge_*` (MERGE on app-level `id`), commits the graph, then upserts schema registry and node embeddings via the worker writer. It returns the Cypher audit trail; the caller commits the SQLAlchemy session. Extraction stamps `organization_id` and KB ID; it never passes ORM objects across its DTO boundary.
- Before MERGE loops, `ingestion.graph.merge_knowledge_base()` calls `ensure_vertex_label` and `ensure_edge_label` once per distinct label (`dict.fromkeys`). AGE's implicit repeated label creation within one transaction can cause `DuplicateTable`; don't remove the preflight.
- Registry key: `(organization_id, graph_name, type, name)`; `type` has a node/relationship check constraint. One label may be shared by multiple KBs; upsert unions/sorts aliases, property names, and `knowledge_base_ids`, filling missing source/target labels. Extraction currently uses `aliases=[]` for both nodes and relationships. `get_properties_by_name(session, graph_name, organization_id, names, type=None)` batches name reads and omits unknown names; empty names short-circuit.
- `KnowledgeBaseService.create_graph()` is a no-op for an existing graph; no SQLAlchemy session needed. `delete_knowledge_base(session, kb_id, graph_name, organization_id)` finds node IDs via that KB's `NodeEmbedding` rows, `DETACH DELETE`s nodes, removes its embeddings, removes its ID from shared registry rows and deletes rows with no remaining KBs. Graph nodes without corresponding embedding rows cannot be found this way. Shared rows retain merged properties/aliases after a KB deletion; re-upsert surviving KBs for exact schema. Registry deletion scans plain JSON IDs in Python to remain SQLite-compatible.
- `delete_graph(session, graph_name, organization_id)` drops the graph if present and clears its organization-scoped side tables **even if absent**; bulk-delete `SchemaEmbedding` children before bulk-delete of `GraphSchemaRegistry` parents (bulk SQL bypasses ORM cascade). Instance `session.delete(parent)` instead uses the relationship's delete-orphan cascade. Graph operations commit their psycopg connection; SQLAlchemy work only flushes and must be committed by the caller. The stores lack a shared transaction; replaying an idempotent write repairs partial progress.

### API-published job DAG (ADR-0005)

- The API publishes an editable KB with at least one file by saving one `queued` `IndexJob` plus one `pending` `IndexFile` per file, fixed `TotalFiles`, and KB state `indexing` in one save. It responds 202 with a `Location` pointing to the job-status GET endpoint; it does **not** publish to RabbitMQ. The EF `AddIndexJobs` migration uses explicit snake_case column names matching worker mappings. A partial unique index on KB ID where status is `queued` or `running` prevents two active jobs (API returns 409 on race).
- `Services/GraphNames.cs` alone computes the AGE graph name at publish: `org_` plus lowercase organization ID with non-`[a-z0-9_]` replaced by `_`; if >63 bytes, use `org_` plus the first 32 hex characters of SHA-256 of the ID, not truncation. `IndexJob.GraphName` is stamped once and read, not recomputed, by the worker.
- RabbitMQ transports Celery tasks; Postgres `index_job`/`index_file` is the source of truth. No Celery result backend and no chord; fan-in is a guarded Postgres counter. Beat's `dispatcher.py` claims queued rows with `FOR UPDATE SKIP LOCKED` and guarded `queued -> running`, commits **before** publishing `extract_ontology`. A crash between commit and publish leaves a job orphaned `running`; `reconciler.py`'s own Beat task (`INGESTION_RECONCILE_INTERVAL_SECONDS`, default 300s) redelivers it — republishing `extract_ontology` when not yet `graph_dispatched`, else `construct_graph` — for any `running` job whose `started_at` predates `INGESTION_RECONCILE_STALE_SECONDS` (default 900s). Both redelivery targets are idempotent re-entry points, so this needs no per-stage special-casing, but there is no per-job last-activity timestamp, so a job still legitimately mid-retry-backoff can be harmlessly redelivered more than once.
- Four **stub-content** stages exist in Celery-free `stages.py`: `extract_ontology(job_id)` fans out `extract_entities(job_id, file_row_id)` for nonterminal file rows; each entity stage conditionally `complete_file()`s its row, increments `record_file_done()` only if it transitioned, then **always** retries `claim_graph_dispatch()` so an interrupted prior delivery can advance. The one winner publishes `construct_graph(job_id)`; it publishes `embed_nodes(job_id, "0")`; this final stage guards `mark_job_completed()` and only on transition sets KB state `published`. Missing/nonrunning jobs skip. Each stage commits before publishing; real file parsing, extraction, graph construction and embedding in these stages remain Phase 2 TODOs. Do not confuse the stub DAG with the working legacy one-shot demo.
- `job_store.py` owns guarded transitions; `jobs.py` has `run_stage` and `fail_job` (failed job and KB state in one commit), `tasks.py` wraps coroutines through `asyncio.run`, retries classified transient failures (429/5xx/timeouts), and records terminal failure. `celery_app.py` routes to `q.ontology`, `q.entity`, `q.graph`, `q.embedding`, each with retry/DLQ queues. **Launch worker with `-Q q.ontology,q.entity,q.graph,q.embedding`**: consuming retry/DLQ queues directly defeats delay/dead-letter behavior. `acks_late` requires guarded transitions, MERGE and idempotent upserts; terminal jobs are skipped.

## Embeddings and vector search (ADRs 0001–0003)

- `GraphSchemaRegistry` metadata is separate from its one-to-one `SchemaEmbedding` child (`graph_registry_id` unique FK). Relationship: `lazy="selectin"`, `cascade="all, delete-orphan"`, `uselist=False`; **no `passive_deletes=True`** (SQLite tests do not enable FK cascades). For new rows, assign `record.embedding_row = None` **before** `session.add` to prevent an autoflush/async lazy-load `MissingGreenlet`; on existing rows mutate the child **in place** or INSERT-before-DELETE hits the unique FK. Search joins child with `contains_eager`.
- `NodeEmbedding` is separate from AGE, uniquely keyed by `(organization_id, graph_name, knowledge_base_id, node_id)`. Both embedding tables have mandatory, indexed, denormalized `organization_id`. Schema search checks the organization on **both** parent and child; no cross-organization search. Node search optionally filters one `knowledge_base_id` and/or multiple `labels`; registry search optionally filters any of `knowledge_base_ids` using PostgreSQL `cast(JSON as JSONB) ?| array(...)`.
- Vectors use **dimensionless** `Vector().with_variant(JSON, "sqlite")`, not a globally fixed width. `EmbeddingService.compute_embeddings(model, texts)` calls `litellm.aembedding` with `model.identifier`, `api_base=connection_string`, API key only for API-key auth, `dimensions=model.embedding_dimension`, and rejects a provider vector of wrong width. `None` model or empty texts skip computation. Worker writer owns `schema_embedding_text`/`node_embedding_text` and stamps `embedding_model_id = model.id` along with each computed vector.
- Vector search requires a model with dimension **before** incurring a billed embedding call. It filters by `organization_id`, graph and **`embedding_model_id == model.id`**, and orders by `cast(embedding, Vector(model.embedding_dimension)).cosine_distance(query_vector)`; never add an independent provenance parameter or use the uncast column. Different models' vectors cannot be ranked together. `database/indexes.py` creates a **partial HNSW expression index per configured model** with the same predicate/cast; >2000 dimensions can be stored/searched but not indexed via HNSW `vector`. ORM classmethods delegate index creation/drop to this leaf helper; do not put HNSW in `__table_args__` (SQLite `create_all` would fail).
- Vector-specific tests compile SQL/`CreateTable` against the PostgreSQL dialect to check casts, predicates, JSONB overlap, dimensionless `VECTOR` and DDL; cosine/JSONB operators do not run in SQLite. Monkeypatch `common.services.embedding_service.litellm.aembedding` rather than making real provider calls. Cover model provenance, width, org isolation, unique KB/node keys, and registry child cascade.

## AGE repository and agent

- `AgeGraphRepository` (`common/repositories/age_graph_repository.py`) is fully async on psycopg3 `AsyncConnection`/`AsyncCursor`; many methods execute Cypher and return its string as an audit trail. `graph_exists` only fetches existence. `create_connection()` runs `CREATE EXTENSION IF NOT EXISTS age` before `LOAD 'age'` (skip LOAD for Azure-hosted Postgres), sets `search_path = ag_catalog, "$user", public`, and **commits setup** before a separate SQLAlchemy connection tries `VECTOR` DDL. Omitting search path breaks AGE `graphid_ops`; omitting commit hides the new extension under MVCC.
- `_parse_agtype()` removes `::vertex`/`::edge` suffixes and JSON-decodes; also accepts bare agtype scalars. `get_node_neighbours` matches the app-level node `id`, walks both directions, deduplicates by AGE's *internal edge ID* (parallel edges are legitimate) and orients endpoints using `start_id`/`end_id`, not binding order.
- `get_node_schema(id)` and `get_label_schema(label)` share `_neighborhood_shape`: one outgoing and one incoming aggregate query, tuples `(relationship_label, direction, neighbor_label, count)` ordered within direction; label-mode counts all nodes of that label, instance-mode counts one node. Validate inlined labels with `str.isidentifier()` before Cypher; values/IDs use `_age_properties_literal`. `label(b)`/implicit grouping has only fake-cursor tests, not a live AGE verification. `search_relationships` uses a directed `(a)-[r:Label]->(b)` and optional endpoint labels/IDs/properties; filters omitted if absent.
- `AgentContext` (`agent_runtime/context.py`) is run-scoped Pydantic data: required `organization_id`, `graph_name`, `attached_kb_ids`, `AsyncSession`, `AgeGraphRepository`, optional **embedding** `Model`; allow arbitrary types. Chat model is construction-time, not context state. `NodeRef(label, id=None)` is for `get_node_schema` lookups; omission selects label mode, blank *present* ID is invalid, and no ID is generated. Do not use auto-ID-generating `KnowledgeNode` for this lookup.
- `tools.py` exports ordered `GRAPH_TOOLS` (import from the leaf, not `agent_runtime.__init__`). Tools use injected `runtime: ToolRuntime[AgentContext]` and require docstrings; don't expose runtime in model-facing descriptions. Reject blank queries/labels before provider/database calls. Return JSON-serializable dicts via `AgentSerializer` (`serializers.py`), not ORM rows. `search_schema_registry` scopes `attached_kb_ids`; `search_entities` optionally filters labels but does **not** pass the multi-ID list into `NodeEmbedding`'s singular KB filter.
- `get_node_schema` switches between repository id/label modes, then separately batches registry property **names** for anchor node (`SchemaType.NODE`), distinct relationship labels (`RELATIONSHIP`) and distinct neighbor labels (`NODE`); unknown labels yield `[]`. Live AGE supplies connections/counts (registry cannot model all neighbor-label pairings). `get_node_neighbours` groups triplets under one anchor with direction; `get_relationship` searches graph-wide by relationship label with optional endpoint filters and returns independent source/edge/target matches.
- `prompts.py` holds `GRAPH_AGENT_SYSTEM_PROMPT` (intentional placeholder); keep prompt out of factory. `chat_model.py`'s `build_chat_model(model, /, **overrides)` maps config to `ChatLiteLLM`: litellm identifier, `api_base`, optional API key; chat-only `reasoning_effort` belongs in `model_kwargs`, not an ignored top-level kwarg; don't pass embedding dimension. Positional-only `model` allows an override named `model`.
- `deep_agent.py` is the sole `build_deep_agent()` assembly site: `Model | BaseChatModel` **required**, `GRAPH_TOOLS`, prompt, `context_schema=AgentContext`, and `[TodoListMiddleware(), *middleware]`. Deepagents defaults supply filesystem/subagent/summarization/tool patching; todo middleware is from `langchain.agents.middleware`. No checkpointer/store or other unused passthrough yet. Default `StateBackend` stores files in graph state, **not host disk**; its advertised `execute` returns an error without a sandbox. Default sequential general-purpose subagent shares context/session; if parallelized, give it its own session. `ChatLiteLLM` has no matching deepagents profile by default, so set `profile={"max_input_tokens": N}` if summarization needs a different trigger. A live agent-to-repository invocation is not yet wired.

## Object storage (ADR-0006, both languages)

- `docs/adr/0006-provider-agnostic-object-storage.md` is the cross-stack contract. Change key/metadata rules or shared disk layout in **both** Python and .NET together. Business code depends on `StorageService` / `IStorageService`, not provider APIs. Python factory imports providers lazily; close services with `aclose()`/`async with`.
- Persist **object keys**, never paths or blob URLs. Keys reject empty/>1024 characters, leading/trailing slash, backslash, controls, drive prefixes, empty/`.`/`..` segments; list prefixes may end in `/` and are plain string prefixes. User metadata names are ASCII identifiers (case-insensitive uniqueness), values ASCII. API supports upload, streamed download, read bytes, idempotent delete, exists, lexicographic list, metadata. Missing reads raise not-found; invalid keys are `ValueError`-compatible; Azure errors retain status code for retry classification without leaking secrets.
- Shared filesystem layout: `root/objects/<key>`, `root/meta/<key>` (**no `.json` suffix**), `root/tmp/` staging. Stream/fsync/atomic replace object then sidecar; mount volume at `root`, not `root/objects`. Sidecars store `content_type`, metadata, etag, size, `mtime_ns`; ignore stale size/mtime (compare at 100 ns resolution with .NET) and fall back to stat. Reject symlink traversal. Filesystem cannot simultaneously store keys `a` and `a/b`; Azure can.
- Python `FileSystemStorage` offloads blocking I/O via `asyncio.to_thread`; `AzureBlobStorage` uses async Azure SDK + aiohttp, staged blocks for streaming, connection string or managed identity, optional lazy container creation. `StorageSettings` resolves `connection_string_env` to `SecretStr`; credentials required only for the selected provider. `STORAGE_PROVIDER`/`STORAGE_FILESYSTEM_ROOT` override YAML. Hide secret values in validation errors.
- .NET `Services/Storage/` implements the same contract independently. `AddStorage` uses bound/postconfigured options with `ValidateOnStart` and registers a singleton; default filesystem root `App_Data/storage` (avoid case-insensitive collision with EF `Data/`). Filesystem streams with MD5 then flush/move; capture `FileInfo` before move. Azure uploads use transfer options. Provider tests use Azurite only if `AZURITE_CONNECTION_STRING` is set; see Python `tests/test_storage_contract.py` and API `GraphPlatform.Api.Tests/Storage/`.

## ASP.NET API (`src/api`)

- `GraphPlatform.slnx` contains API and test projects. Code is organized under `Controllers/`, `Dtos/`, `Data/`, `Models/`, `Services/`, `Extensions/`; all DTOs use namespace `GraphPlatform.Api.Dtos` despite subfolders (avoid `Dtos.Models` name collision). Hand-map responses in `Dtos/DtoMappings.cs`, especially secrets: `ModelDto` exposes `HasApiKey`, never the key.
- `Data/AppDbContext.cs` uses `IdentityUserContext<AppUser>`: organization roles are in `user_organization.Role`, not Identity roles. JWT contains identity only; membership/role is reread per request. `organization_id` is `varchar(255)`/string, not Guid; `ModelConfig.Id` is also a string validated as UUID. Persist/serialize enum names in lower snake-case via `SnakeCaseEnum<T>()` and global `JsonStringEnumConverter(SnakeCaseLower)`; plain `HasConversion<string>()` would write `ApiKey`. `ModelConfig.Type` is JSON array in `jsonb` via string converter.
- API model writes require `apiKey` unconditionally; no editable `authMode` (stored/read as `api_key`), unlike Python YAML's managed identity. Enforce nonempty type, embedding exclusive of vision/thinking, embedding dimension required and reasoning effort forbidden for embedding; `[ApiController]` produces 400 validation problems.
- `KnowledgeBase` resource has no inline graph payload. `KnowledgeBase.IsEditable` is `draft` **or `failed`**; Contributor/Admin may edit/delete/publish/upload/delete files in those states, permitting retry after ingestion failure. Publish requires at least one file; worker moves completed jobs to `published` and failed ones to `failed`. Nonmembers get 404 (no org existence leak); members without mutation role get 403. Creating organizations is open to authenticated users; last admin removal/demotion and deletion of active embedding model return 409. Any member may read jobs/KBs/files; cross-org/unknown job reads return 404.
- File entity is owner-agnostic; `knowledge_base_file` links it to KBs. `File` collides with `System.IO.File`: use a **local** `using File = GraphPlatform.Api.Models.File;` where needed, not global; in controllers use `Models.File.FileNameMaxLength` where `ControllerBase.File` takes precedence. `FileService.CreateAsync` uploads before DB save and best-effort removes object on save failure; `RemoveAsync` deletes objects **before** marking DB rows for removal, so failed storage leaves rows retryable. Owner delete paths call it; DB cascades cannot delete objects. Keys: `organizations/{orgId}/files/{fileId}/content` (no filename/owner). `FileDto` does not reveal storage key. Sanitize filenames and normalize empty content type.
- `KnowledgeBaseFilesController` supports multipart `file` POST, list, metadata, streamed content GET, delete; ownership lookup goes through the link. `KnowledgeBaseDto.Files` is oldest first. Upload default limit 100 MiB, startup-validated via `FileUploads:MaxFileSizeBytes`; apply `FileUploadLimitsFilter` **before model binding** to raise Kestrel and multipart limits. Missing/empty part 400, oversized 413, no content-type allow-list.
- Job-status DTOs are hand-mapped (`IndexJobDto` includes counters, file statuses/errors). `AppDbContext` maps job/file FKs and a partial unique active-job index; a plain and partial-unique index on the same KB column each need distinct names **inside their separate `HasIndex(...)` calls**, not only later `HasDatabaseName`, or EF collapses them.
- `ConnectionStrings:PgConnectionString` is read directly via `AppDbContext.ConnectionStringName` (also used by design-time factory); no `.env`/PG* fallback. **Missing/empty value does not fail fast**: Npgsql can silently use defaults. Development connection string and JWT signing key belong in gitignored `appsettings.Development.json` or env `ConnectionStrings__PgConnectionString`/`Jwt__SigningKey`; committed `appsettings.json` has empty stubs. `Database:AutoMigrate` defaults false; migrate deliberately, or via one-shot `api-migrations` container before API startup.
- `Program.cs` installs SPA CORS after HTTPS redirection and before authentication. `Cors:AllowedOrigins` defaults to localhost Vite dev/preview (`5173`, `4173`); enumerate origins with credentials, expose `Content-Disposition` for browser downloads.
- API integration tests use `WebApplicationFactory` with SQLite `EnsureCreated` instead of running Npgsql migrations; use xunit **2.x** + `Microsoft.NET.Test.Sdk` + `xunit.runner.visualstudio` on .NET 10 (xunit.v3/MTP did not run correctly here). PostgreSQL migration/jsonb round-trip needs separate live verification.

## Frontend (`src/frontend`)

- Vite 8, React 19 + React Compiler, TS 6, Tailwind v4, shadcn/ui, React Router 7, TanStack Query 5, React Hook Form/Zod 4. npm project. `src/components/ui/**` is generated: don't hand-edit; after `shadcn add`, fix type imports with `npx eslint src --fix` then `npx tsc -b`.
- `@/*` alias must agree in root `tsconfig.json`, `tsconfig.app.json`, `vite.config.ts`; no TS6-deprecated `baseUrl`. `erasableSyntaxOnly` forbids TS enums/parameter properties; use const objects + unions. `verbatimModuleSyntax` requires type-only imports. Tailwind tokens live in `src/index.css`, not a `tailwind.config.js`.
- Committed `.env` defines `VITE_APP_NAME`, `VITE_API_BASE_URL`, `VITE_MAX_UPLOAD_BYTES`; `.env.local` is ignored. `src/app/env.ts` prefers `window.__APP_CONFIG__` from runtime `/config.js`, then Vite defaults; Docker entrypoint renders `FRONTEND_APP_NAME`, `FRONTEND_API_BASE_URL`, `FRONTEND_MAX_UPLOAD_BYTES` on startup. Runtime changes need only container restart. Defaults: GraphForge, `http://localhost:5087`, 104857600 bytes.
- HTTP errors are not uniformly JSON: 401/403 can have empty bodies; validation problems carry `errors`; network failures map to status 0. `getFieldErrors` handles mixed Pascal/camel case, `$`, and `file`. Upload with XHR for progress; multipart key exactly `file`, never manually set Content-Type. Download through authenticated blob fetch and object URL (defer URL revoke for Safari).
- Access token lasts 60 minutes, no refresh token: warn T−5 min, logout T−30 s, rearm on visibility change; 401 triggers one logout, except login/signup's `skipAuthRedirect`. Organization scope is in `/orgs/:organizationId/...`, not global state; lastOrgId is redirect hint only. Roles come from `/api/auth/me`, not JWT; `src/org/permissions.ts` mirrors API `canAuthor`/`canGovern` and editable KB (`draft`/`failed`). Disable actions with a reason/tooltip (`ActionTooltip` wraps disabled buttons); mirror fileless-publish, last-admin, active-model, and noneditable-KB 409s.
- Editing a model replaces it wholesale and needs reentered API key; no auth selector, no fake secret or visible/resource ID. Capabilities enforce nonempty type and exclusive embedding vs vision/thinking; show dimension or reasoning effort contextually. `newUuid` is only a client-side upload-row key. List filtering/paging via `useClientCollection` is client-side until API endpoints support it. Polling returns 5 seconds only for indexing KBs or uploaded/processing files, else false.
- React Compiler disallows synchronous effect `setState`: dialog form state resets via Radix unmount; `useIsMobile` uses `useSyncExternalStore`; `ModelForm` uses `useWatch`. `next-themes` uses `attribute="class"` to match Tailwind dark variant; ThemeToggle offers Light/Dark/System, using `resolvedTheme` for its icon, in both authenticated shell and auth layout. Preserve skip link, route-change main focus, aria-live status announcements, dialog titles and destructive alert dialogs; don't rely on color alone.

## Docker and local checks

- Docker runbook: `docker/README.md`. All image build contexts are repository root; `docker/compose.infra.yaml` defines Postgres/RabbitMQ/Redis and is included by `docker/compose.yaml` (full stack). The `postgres:18.6-trixie`-based image builds official AGE 1.8.0 + pgvector 0.8.6; its init SQL creates extensions. AGE's `search_path`/LOAD are still per connection (see repository section). API image doubles as `api-migrations`; Python worker image serves schema-init, worker and Beat; agent-runtime image has no Compose HTTP service; frontend is nginx on `8080`.
- Copy `docker/.env.example` to ignored `docker/.env`; keep API and Python DB settings pointing at the **same** Postgres DB (container hostname `postgres`, host uses `POSTGRES_HOST_PORT`). Never embed model/storage secrets in YAML. `CORS_ALLOWED_ORIGIN` must match browser-visible frontend. RabbitMQ password goes into an AMQP URI, so choose URI-safe alphanumeric characters.
- Full stack gates API on one-shot EF migrations and worker/Beat on `python-schema-init` and broker health. Schema init runs `Base.metadata.create_all` and indexes for the first embedding model; it does not create EF-owned tables. Persistent PG volume mounts at `/var/lib/postgresql` (PG18 PGDATA is `/var/lib/postgresql/18/docker`); shared storage volume mounts at `/data/storage`, not its `objects` subdirectory. `configs/local.yaml` is read-only-mounted, so restart Python containers after config edits.

Run focused checks in the appropriate project; root `uv run pytest` cannot resolve a root project:

```sh
uv run --project src/common pytest tests/ -o asyncio_mode=auto
uv run --project src/agent-runtime pytest src/agent-runtime/tests
uv run --project src/ingestion-worker pytest src/ingestion-worker/tests
dotnet test src/api/GraphPlatform.slnx
cd src/frontend && npm run lint && npx tsc -b && npm run build
docker compose --env-file docker/.env -f docker/compose.yaml config
```

For Python, repository/lifecycle and model tests are in root `tests/`; ingestion/DAG tests live in `src/ingestion-worker/tests/`; agent tools/serializers/factory tests in `src/agent-runtime/tests/`. Prefer SQLite and fake async cursors/sessions; compile PostgreSQL-only statements against the PG dialect. API endpoint/storage tests are in `src/api/GraphPlatform.Api.Tests/`; frontend lints, type-checks and builds. Live AGE, pgvector, Azurite and real provider behavior require separate integration/evaluation runs.
